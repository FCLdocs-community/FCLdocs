# Minecraft Java版 如何被移植到手机上？

## 问题：Minecraft Java 版能在手机上运行吗？

**直接运行：不能。** 原因有三：

1. **需要 [Java](window:/term/Java) 虚拟机（[JVM](window:/term/JVM)）**：Minecraft Java 版依赖标准 JVM，而 Android 自带的 ART 是高度定制的运行时，无法运行标准 Java 字节码。
2. **图形接口不同**：Minecraft 使用桌面版 OpenGL，手机使用 OpenGL ES / Vulkan，两者不兼容。
3. **[CPU](window:/term/CPU) 架构不同**：桌面版运行库针对 x86 架构编译，手机多为 ARM 架构，CPU 无法直接执行。

**间接运行：可以。** 使用 **[PojavLauncher](https://github.com/PojavLauncherTeam/PojavLauncher)（已停止维护）/ [Amethyst](https://github.com/AngelAuraMC/Amethyst-Android) / Fold Craft Launcher / [ZalithLauncher](https://github.com/ZalithLauncher/ZalithLauncher)** 等启动器，可以在手机上运行 Java 版。下面说明原理。

## 关键概念：什么是 `.so` 文件？

**`.so` 文件**全称 **Shared Object**，即**共享库**或**动态链接库**，是 Linux/Android 上的可执行代码库，相当于 Windows 上的 `.dll`。

程序可以用到某个功能时，把这段功能的代码写成一个独立的库（`.so`），运行时再加载调用，而不是把全部代码编进主程序。这样既节省体积，也能让多个程序共享同一个库。

`.so` 文件的特点：

- 是**编译后的机器码**，CPU 能直接执行；
- **与架构相关**：针对不同芯片架构、不同 libc 环境的 `.so` 一般不通用；
- 多个程序能**共享**同一个 `.so`，节省存储；
- Linux/Android 的系统核心库都是 `.so`，如 `libc.so`（C 标准库）、`libGL.so`（OpenGL 库）。

:::note 名词解释
**动态链接库**：程序运行时才加载的代码库，不是编译时静态打包进去的。好处是省空间、可共享、可单独更新。
:::

## 关键概念：Android 和 Linux 的关系

**Android 的底层是 Linux 内核**。用户在 Android 上看不到 Linux 命令行，但底层确实是 Linux。需要注意：

- Android 的用户空间使用 **Bionic libc**，与标准 Linux 的 **glibc** 不同；
- 因此**桌面 Linux 的 `.so` 不能直接复制到 Android 使用**，必须针对 Android 重新编译；
- Android 的 `/system/lib/`、`/system/lib64/` 中都是 `.so` 文件；
- App（[APK](window:/term/安装包)）中也能携带 `.so`，放在 `lib/` [目录](window:/term/文件夹)下。

## Minecraft Java 版在电脑上如何运行

电脑上运行 Minecraft Java 版的流程：

```
1. 启动器（Launcher）启动
       ↓
2. 启动 JVM（Java 虚拟机）
       ↓
3. JVM 加载 Minecraft 的 .jar 文件（字节码）
       ↓
4. JVM 将字节码翻译为 x86 机器码，在 CPU 上执行
       ↓
5. Minecraft 调用电脑的 OpenGL 库（libGL.so / opengl32.dll）绘制画面
       ↓
6. 画面显示在屏幕上
```

关键点：

- **JVM 是关键**：没有 JVM，字节码无法运行；
- **OpenGL 库是关键**：没有图形库，画面无法绘制；
- **CPU 芯片是关键**：JVM 翻译出的机器码需与 CPU 架构匹配。

## 手机上的三个难点

### 难点 1：手机没有 Java 虚拟机

Oracle 没有为 Android 提供官方 JVM。解决方案是使用开源的 [OpenJDK](https://openjdk.org/)：PojavLauncher 团队（以及后来的继任项目）将 OpenJDK 移植到 Android、编译为 ARM 架构 Android 环境的可执行文件，并打包进 APK。

> 在 PojavLauncher 团队的基础上，国内开发者（以 Tungstend 为代表的 FCL-Team、墨北 MovTery 等）分别推出了 Fold Craft Launcher、ZalithLauncher 等改进版本，在底层移植工作之上自行移植了部分 `.so`，并优化了界面、控制方案与[渲染器](window:/term/渲染器)支持。详见 [Java 移植](/SuperDocs/手机启动器原理/Java%20移植)。

### 难点 2：手机图形接口不同

电脑 Minecraft 使用 **OpenGL**（桌面版），手机使用 **OpenGL ES**（移动版，功能较少）或 **Vulkan**，两者不兼容。

> **补充**：从 Minecraft 26.2 起，游戏新增了 **Vulkan 渲染后端**（实验性），可在图形设置中选择"优先使用 Vulkan（实验性）"或"优先使用 OpenGL"，不支持 Vulkan 的硬件会回退到 OpenGL；使用 Vulkan 的系统要求是支持动态渲染与推送描述符的 Vulkan 1.2。这让新版本在手机上可以省去部分转换损耗。

解决方案是使用**图形接口转换层**。手机 Java 启动器用到的主要有：

- **[LWJGL](https://www.lwjgl.org/)**：Minecraft 使用的游戏基础库，PojavLauncher 将其移植到 Android；
- **[GL4ES](https://github.com/ptitSeb/gl4es)**：将 OpenGL 调用转换为 OpenGL ES，Minecraft 1.16.5 及更早基本使用该后端；
- **[ANGLE](https://github.com/google/angle)**：Google 开发的转换层，将 OpenGL ES 调用转换为 Vulkan，通常作为第二层使用；
- **VirGL/其他 Mesa [驱动](window:/term/驱动)**：将 OpenGL 调用转换为 Vulkan 或 OpenGL ES。

简单来说：**Minecraft 调 OpenGL → 转换层转换为 OpenGL ES / Vulkan → 手机 [GPU](window:/term/GPU) 绘图**。

### 难点 3：CPU 芯片不同

电脑多为 x86 芯片（Intel/AMD），手机为 ARM 芯片。Java 字节码本身跨平台，但 JVM 翻译出的机器码必须匹配 CPU 架构。解决方案是使用 **ARM 版 Java 虚拟机**：OpenJDK 支持 ARM，但标准版针对桌面 Linux 的 glibc 编译，需针对 Android 的 Bionic libc 重新编译。

## PojavLauncher 是如何实现的？

PojavLauncher 是一个开源项目，将 Minecraft Java 版运行在 Android 上，核心组成如下：

| PojavLauncher APK 内容 |
|---|
| 1. 启动器界面 |
| 2. ARM 版 JVM（libjvm.so） |
| 3. LWJGL 移植版（liblwjgl.so） |
| 4. GL4ES / VirGL / ANGLE（图形转换层） |
| 5. Minecraft .jar 文件（用户[下载](window:/term/下载)） |

启动流程：

1. 用户打开 PojavLauncher，登录 Minecraft 账号；
2. 启动器从 Mojang 官方[服务器](window:/term/服务器)下载 Minecraft Java 版的 `.jar` 文件；
3. 启动器启动 **ARM 版 JVM**（`libjvm.so`）；
4. JVM 加载 Minecraft 的 `.jar`，将字节码翻译为 ARM 机器码；
5. Minecraft 调用 OpenGL 绘图 → **GL4ES / VirGL / ANGLE 转换为 OpenGL ES / Vulkan** → 手机 GPU 渲染；
6. 画面显示在手机屏幕上。

关键在于几个 `.so` 文件：`libjvm.so`（Java 虚拟机）、`liblwjgl.so`（游戏基础库）、`libgl4es.so`（图形转换）。它们都是**针对 Android、ARM 架构与 Bionic libc 重新编译**的共享库，因此能在 Android 上运行。

## 类似的启动器

除 PojavLauncher 外，还有：

- **[Amethyst](https://github.com/AngelAuraMC/Amethyst-Android)**（Android/iOS）：PojavLauncher 团队的官方续作；
- **HMCL PE**（Android）：老牌启动器，已停更；
- **Fold Craft Launcher**（Android）：国产，优化较好；
- **[ZalithLauncher](https://github.com/ZalithLauncher/ZalithLauncher)**（Android）：基于 PojavLauncher 二次开发，界面与功能更完善。

## 性能表现

手机运行 Minecraft Java 版的[帧率](window:/term/帧率)因芯片档次差异极大，共同瓶颈包括：

- **图形转换损耗**：OpenGL → OpenGL ES / Vulkan 的转换存在性能损失；
- **散热限制**：手机体积小，长时间运行会发热降频，帧率从峰值下降；
- **电池续航**：高帧率下耗电快，插电运行才能维持峰值性能。

以下是部分实测参考（原版 = 未加任何优化[模组](window:/term/mod)，版本参考 1.21，[视距](window:/term/视距) 8 区块）：

| 芯片档次 | 测试芯片 | 原版帧率 | 加优化模组后 | 体验 |
|---|---|---|---|---|
| **顶级旗舰** | 骁龙 8 Elite | 350–500 | 420–900+ | 非常流畅 |
| **高端** | 骁龙 8s Gen3 | 110–310 | 260–500 | 流畅，运行 mod 无压力 |
| **中高端** | 骁龙 7 系（新款） | 130–300 | 170–540 | 日常流畅，多数场景稳 60+ |
| **中端老旗舰** | 骁龙 865 / 870 | 90–180 | 100–320 | 能玩，复杂场景会掉帧 |
| **中低端** | 骁龙 6 系、天玑 800 系 | 30–60 | 40–100 | 可玩，需降低画质 |
| **入门** | 骁龙 4 系、天玑 700 | 10–30 | 20–70 | 需搭配优化[整合包](window:/term/整合包) |

说明：

- **优化模组**：可提升游戏帧率，手机 Java 启动器基本都支持安装；
- **帧率与场景相关**：表中为正常地形、正常[分辨率](window:/term/分辨率)下的峰值，复杂地形、大量方块、开启[光影](window:/term/光影)时会明显下降；
- **发热降频**：手机长时间运行会发热并降频，"能跑 900 帧"不等于"一直稳定 900 帧"；
- **重度 mod**（如 RLCraft、大型整合包）：即使旗舰机也可能掉到 50–120 帧，中低端机可能严重卡顿。
