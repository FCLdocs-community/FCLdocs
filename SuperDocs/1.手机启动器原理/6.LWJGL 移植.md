# LWJGL 移植

[JVM](window:/term/JVM) 能运行之后，Minecraft 启动的第一件事是创建窗口、初始化 OpenGL——这些能力由 **LWJGL** 提供。LWJGL 与 JVM 一样不是为 Android 设计的，因此需要单独的移植工作。

## LWJGL 在 Minecraft 中承担什么

LWJGL（Lightweight [Java](window:/term/Java) Game Library）是一套让 Java 程序调用底层图形、音频、输入能力的绑定库。Minecraft 主要使用其中三部分：

| 模块 | 作用 | Minecraft 的用法 |
|---|---|---|
| **GLFW** | 窗口、输入（键鼠/[手柄](window:/term/手柄)）、OpenGL 上下文管理 | 创建游戏窗口、读取输入、对接图形 API |
| **OpenGL 绑定** | 将 OpenGL 的 C 接口包装为 Java API | 全部画面绘制 |
| **OpenAL 绑定** | 3D 音效接口 | 游戏声音 |

其中 GLFW 是关键。它是 C 语言库，在桌面上依赖 X11/Wayland/Win32 等**桌面显示系统**来创建窗口——Android 上没有这些系统，也没有桌面版 OpenGL。这就是 LWJGL 无法直接在 Android 上运行的原因。

## Pojav 的改造思路：保留接口，替换实现

PojavLauncher 团队的方案（仓库 [PojavLauncherTeam/lwjgl3](https://github.com/PojavLauncherTeam/lwjgl3)）不是把 GLFW 移植到 Android，而是**保持 GLFW 的 Java 接口不变，把内部实现整体替换**：

**1. 重写 `org.lwjgl.glfw.GLFW`**

- `glfwCreateWindow()` 等窗口调用 → 改为把 Android 的 `Surface`（可供 [GPU](window:/term/GPU) 绘图的原生窗口）注册为渲染目标；
- `glfwPollEvents()` 等输入调用 → 改为从一条事件管道中读取启动器写入的消息。

```
桌面：  Minecraft → LWJGL → GLFW(C库) → X11/Win32 → 键盘鼠标
Android：Minecraft → LWJGL → 事件管道 ← 启动器采集触摸/按键/手柄
                      ↓
              ANativeWindow(Surface) → EGL → GLES
```

**2. 输入事件桥（CallbackBridge）**

启动器侧采集 Android 的触摸、按键、手柄事件，转换为 GLFW 的键码语义（`GLFW_PRESS`、`GLFW_MOUSE_BUTTON_1` 等），经 `CallbackBridge` 写入 native 输入队列；游戏侧按普通 GLFW 事件消费。游戏本身感知不到差别——虚拟鼠标、虚拟按键等功能的实现基础就在这里。

**3. 引入 lwjglx 兼容 LWJGL 2**

Minecraft 1.12.2 及更早版本基于 LWJGL 2，接口与 3 不兼容。Pojav 打包了 [LWJGLX](https://github.com/PojavLauncherTeam/lwjglx)（LWJGL2→LWJGL3 兼容层），使老版本也能运行在改造后的 LWJGL 3 上。

## FCL 中的 LWJGL

FCL 在此基础上进一步完善，对应仓库中的 `LWJGL/` 模块。

### 两个版本并存

Minecraft 不同版本对 LWJGL 有硬性要求，FCL 内置两套：

| 内置版本 | 对应 Minecraft 版本 | 说明 |
|---|---|---|
| **3.3.3** | 1.12.2 ~ 1.21.x | 以 Java 8 编译，兼容老 JVM，为默认值 |
| **3.4.1** | 26.x | 配合 26.x 的渲染与输入改动，需较新 JVM |

构建时（`LWJGL/3.4.1/build.gradle.kts`）将官方 lwjgl 各模块 jar 合并并应用补丁，产出 `lwjgl-<版本>-merged-modules.jar` 放入 [APK](window:/term/安装包) 的 `assets/app_runtime/lwjgl/<版本>/`；各架构的 native 库[解压](window:/term/压缩包)到 `runtime/lwjgl/<版本>/natives/<架构>/`，通过 `LD_LIBRARY_PATH` 提供给 JVM。

### FCL 的补丁内容

对比官方 LWJGL，FCL 的 LWJGL 模块（`LWJGL/3.4.1/src/`）包含：

- `org/lwjgl/glfw/GLFW.java`、`CallbackBridge.java`：替换 native GLFW 的窗口/输入桥（Pojav 血统）；
- `org/lwjgl/opengl/PojavRendererInit.java`：按 `POJAV_RENDERER` 环境变量选择渲染后端；
- `org/lwjgl/sdl/SDLInit.java`、`SDLMouse.java`：**SDL3 支持**。自 26.3 起，Minecraft 改用 SDL3 而非 GLFW 处理窗口管理、输入与平台集成，FCL 于 2026 年 9 月集成 SDL3 绑定（以 ZalithLauncher2 的实现为参考）以支持 26.3+；
- `LWJGL/shared/` 中的 **JSound**：将桌面 Minecraft 使用的 `javax.sound` 调用桥接到 OpenAL，解决音频兼容。

### 启动参数的汇合点

游戏[日志](window:/term/日志)中的启动命令有三个占位符在启动时被替换（`FCLauncher.rebaseArgs()`）：

```
-Djava.library.path=${natives_directory}    ← LWJGL natives 目录
-Dorg.lwjgl.opengl.libname=${gl_lib_name}   ← 渲染器 GL 库
-Dorg.lwjgl.egl.libname=${egl_lib_name}     ← 渲染器 EGL 库
```

LWJGL 据此知道从哪里加载[渲染器](window:/term/渲染器)的库——[Java 移植](/SuperDocs/手机启动器原理/Java%20移植)、LWJGL、[渲染器](/SuperDocs/手机启动器原理/渲染器)三条线在此汇合。

:::note lwjgl3ify 实例
1.7.10 / 1.12.2 的大型 Forge 整合包常依赖 **lwjgl3ify**，它让老 Forge 运行在 Java 17+ 与 LWJGL3 上。FCL 对含 `config/lwjgl3ify.cfg` 的实例做了专门适配（注入 `XDG_DATA_HOME` 等），大多数 lwjgl3ify 整合包可以直接运行。
:::
