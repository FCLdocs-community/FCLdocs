# 渲染器

在手机 Minecraft [Java](window:/term/Java) 版语境下，"[渲染器](window:/term/渲染器)"指 **[OpenGL](window:/term/OpenGL) 的实现方式**，即用什么办法把游戏的 OpenGL 调用转换为手机 [GPU](window:/term/GPU) 能执行的指令（概念见[什么是图形渲染器](/SuperDocs/手机启动器原理/什么是图形渲染器)）。本节是实操向内容：FCL 中每个渲染器的定位、适用场景与扩展机制。

## 为什么需要多个渲染器

没有一种渲染器能覆盖所有组合。Minecraft 版本跨度大（1.7 至 26.x），着色器复杂度不断上升；手机 GPU 又分 Adreno、Mali、PowerVR 等流派。因此 FCL 内置五个渲染器，并支持[插件](window:/term/插件)扩展。

## 内置渲染器一览

（对应源码 `com.mio.manager.RendererManager`，数据来自 FCL 1.3.4.5）

| 渲染器 | 库文件 | 原理 | 兼容上限 | 适用 |
|---|---|---|---|---|
| **Krypton Wrapper**（NG-GL4ES） | `libng_gl4es.so` | gl4es 深度改造，GLES3 + SPIRV-Cross 着色器转换 | 26.2 | **默认**，均衡之选 |
| **Holy-GL4ES** | `libgl4es_114.so` | 经典 OpenGL→GLES2 转换层 | 1.21.4 | 老版本、低配机、求稳 |
| **VGPU** | `libvgpu.so` | 轻量虚拟 GPU，模拟固定管线 | 1.16.5 | 远古版本（1.8 / 1.12.2） |
| **Zink** | `libglxshim.so` + `libEGL_mesa.so` | Mesa 官方 OpenGL→[Vulkan](window:/term/Vulkan) 实现 | 26.2 | 新版本 + 好[驱动](window:/term/驱动)，冲性能 |
| **MobileGlues** | `libmobileglues.so` | 专为 MC 设计的 GL 实现（基于宿主 GLES 3.x） | 无上限 | 26.x、跑[光影](window:/term/光影) |

:::note 关于"兼容上限"
表中数值取自 FCL 源码注册信息。Zink 与 Krypton Wrapper 对内门控至 26.3-snapshot-3，但面向用户展示的兼容上限为 26.2。
:::

### 各渲染器说明

**Holy-GL4ES**：上游是 [HolyGL4ES](https://github.com/AngelAuraMC/HolyGL4ES)（ptitSeb gl4es 面向 Minecraft 的修复分支），`libgl4es_114.so` 对应 gl4es 1.1.4 系列。其核心能力是**[固定管线模拟（FPE）](window:/term/FPE)**：在 GLES2 上模拟老版本 Minecraft 使用的 OpenGL 1.x 固定管线。着色器转换能力弱，这是它兼容上限为 1.21.4 的原因。

**VGPU**：FCL 于 2023 年加入的轻量方案，用软件方式补齐固定管线，只覆盖 1.16.5 及更早版本，特点是占用小、兼容老版本与老[模组](window:/term/mod)。

[Zink](window:/term/Zink)：出自 [Mesa](https://gitlab.freedesktop.org/mesa/mesa) 的官方实现，将 OpenGL 编译为 **Vulkan**。能力上限高（向游戏声明 OpenGL 4.6 支持），但依赖 Vulkan 驱动质量——Adreno 设备配合 Turnip 驱动效果明显，Mali 设备则取决于系统驱动。带[着色器缓存](/SuperDocs/手机启动器原理/着色器)。

**[Krypton Wrapper（NG-GL4ES）](window:/term/KryptonWrapper)**：[NG-GL4ES](https://github.com/ShirosakiMio/NG-GL4ES) 是 gl4es 的现代化分支，用 glslang + SPIRV-Cross 提高着色器转换能力，走 GLES3 路线，兼容上限至 26.2，是当前默认渲染器。

[MobileGlues](window:/term/MobileGlues)：[MobileGlues](https://github.com/MobileGL-Dev/MobileGlues-release) 是社区项目，专为 Minecraft 优化，支持 [Sodium](window:/term/Sodium)、大多数 [Iris](window:/term/Iris) 光影以及 Create 等自绘 mod，可选配 ANGLE 二层。FCL 自 2026 年 10 月起将其内置，并提供运行时设置界面（环境变量、MultiDraw 方案等），26.x 推荐使用。

## 渲染器插件机制

自 2024 年 10 月起（提交 `Feat[Plugin]: renderer plugin`），FCL 将渲染器插件化，渲染支持可以脱离启动器本体更新。参考 [FCLRendererPlugin](https://github.com/ShirosakiMio/FCLRendererPlugin) 模板：

- 插件是一个普通 [APK](window:/term/安装包)，在 manifest 的 meta-data 中声明 `fclPlugin=true` 以及渲染器名称、描述、环境变量；
- 新版（v2）格式通过插件内 JSON 资源声明**可配置项**（下拉选择 / 自定义输入 / 开关），FCL 在渲染器"齿轮"对话框中直接生成配置界面，配置持久化到启动器 DataStore；
- 启动时，FCL 将插件[解压](window:/term/压缩包)出的库[目录](window:/term/文件夹)注入 `LD_LIBRARY_PATH`，并按插件声明的 `DLOPEN`、`LIB_MESA_NAME`、`POJAVEXEC_EGL` 等环境变量加载渲染库（源码 `FCLauncher.addRendererEnvInner()`）；
- [VirGL](window:/term/VirGL)（`gallium_virgl`，配套 `virgl_test_server`）、**Freedreno** 等均通过此机制引入。

## 驱动插件：渲染器的地基

对 Zink 这类走 Vulkan 的渲染器，效果取决于 **Vulkan 驱动**质量。系统驱动不理想时可自行更换驱动，参考 [FCLDriverPlugin](https://github.com/FCL-Team/FCLDriverPlugin) 模板：

- 将开源 GPU 驱动的 `.so`（Adreno 的 [Turnip](window:/term/Turnip)：`libvulkan_freedreno.so`；Mali 的 [panvk](window:/term/panvk)）打包为 APK 安装；
- 在「版本设置 → 驱动」中选择后，FCL 将插件库目录作为 `DRIVER_PATH` 传入游戏进程，native 层的 **linkerhook** 拦截 Vulkan 加载器的 `android_dlopen_ext`，将系统驱动替换为插件驱动；
- `DRIVER_GPU` 标明适配的 GPU 家族（adreno / mali / any），不匹配则回退系统驱动；
- 若设备驱动存在功能缺口，FCL 的 [vkshim](window:/term/vkshim) 可自动包一层补齐（2026 年 11 月加入 Vulkan 设备检测与能力补全）。

## 选择建议

| 情况 | 推荐 |
|---|---|
| 一般版本，不折腾 | Krypton Wrapper（默认） |
| 26.x 新快照 | MobileGlues 或 Zink |
| 1.8 ~ 1.16.5 远古版本 | VGPU 或 Holy-GL4ES |
| 想跑光影 | MobileGlues（可选挂 ANGLE） |
| Adreno 芯片冲性能 | Zink + Turnip 驱动插件 |
| 启动报 GL 相关错误 | 先换渲染器，再对照[渲染器选择错误](/SuperDocs/报错解决/渲染器选择错误) |

## 演进时间线（来自 FCL 提交历史）

```
2022.10  项目创建（继承 Amethyst 后端的 gl4es / virgl 基础）
2023.03  加入 VGPU 渲染器
2023.09  Zink 渲染器落地
2024.03  Freedreno 渲染库 / Turnip 驱动适配
2024.10  渲染器插件机制 + LTW 渲染器
2026.09  集成 SDL3，支持 26.3+（以 ZalithLauncher2 为参考）
2026.10  内置 MobileGlues + SimpleFPEWrapper（SFPEW）兼容层
2026.11  Vulkan 设备检测与 vkshim 驱动能力补全
```

:::note SFPEW 是什么
SimpleFPEWrapper 是一层"兼容包装"：当某些新渲染后端不支持老版本的固定管线时，由它模拟补齐，使"新渲染器 + 老版本"也能组合。FCL 内置 MobileGlues 时默认启用。
:::
