# 游戏加载错误

这里说的「游戏加载错误」，指点了启动之后、还没进入主界面就失败的情况：启动器弹出「无法启动」、游戏窗口没有出现，或者一直卡在加载界面。

如果已经进入世界才[崩溃](window:/term/崩溃)，看 [Crash报错](/SuperDocs/报错解决/Crash报错)；如果是 [Java](window:/term/Java) 虚拟机自己抛出的异常，看 [Java虚拟机报错](/SuperDocs/报错解决/Java虚拟机报错)。

## 先看卡在哪一步

启动时会依次经过：解析版本、扫描[模组](window:/term/mod)、检查依赖、[下载](window:/term/下载)依赖、检查 Java、登录、等待游戏启动。启动器停在哪一步，问题通常就在那一步。

## 先拿到日志

- **游戏[日志](window:/term/日志)**：`/sdcard/FCL/log/latest_game.log`，保存最近一次启动的游戏输出。
- **游戏内查看**：菜单 → 设置 → 「显示日志」或「自动显示日志」。
- **启动器日志**：启动器设置 → 「导出启动器日志」，或者在管理页打开「浏览 FCL 日志[文件夹](window:/term/文件夹)」。
- **崩溃报告**：开启[版本隔离](window:/term/版本隔离)时，在 `.minecraft/versions/<版本>/crash-reports/` 下。

打开日志后直接搜索这些关键词：`Exception`、`Error`、`Caused by`、`Missing`、`failed`、`Could not`。先看最后一段[报错](window:/term/报错)，再往上找第一个 `Caused by`。

## 日志里能直接看出的情况

- `Class path entries reference missing files: ... - the game may not load properly!`
  版本 jar 不在 classpath 里，通常是文件被删、下载不完整或版本目录被移动。
- `Minecraft game provider couldn't locate the game! The game may be absent from the class path, lacks some expected files, suffers from jar corruption or is of an unsupported variety/version.`
  游戏 jar 缺失、损坏，或者安装方式不被支持。按下面的「游戏文件缺失或损坏」处理。
- `Detected unexpected shutdown during last game startup: resetting fullscreen mode`
  上次异常退出后的正常提示，不是错误，可以忽略。
- `Failed to load a library`
  本地库或 [LWJGL](window:/term/LWJGL) 加载失败，按 [Java虚拟机报错](/SuperDocs/报错解决/Java虚拟机报错) 的本地库部分处理。
- `java.lang.IllegalStateException: Game version not set`
  版本参数或版本文件异常，常见于新快照，先更新启动器再试。

## 启动器弹「无法启动」

### 依赖下载失败

常见文案：

- `未能下载游戏依赖 xxx`
- `下载失败: <链接>，错误码：404`
- 下载超时

处理顺序：

1. 启动器设置里切换下载源，再重试。
2. 检查[存储空间](window:/term/存储空间)是否不足。
3. 在版本管理里检查资源文件完整性。
4. 仍然失败就删除该版本重新下载。

### 文件校验失败或下载中断

常见文案：

- `无法校验文件。`
- `文件下载中断，你可以切换下载源以尝试修复此问题。`

这类基本是下载过程被中断或文件损坏。换下载源重下即可，不要手动改 jar 或补文件。

### 找不到合适的 Java

文案是 `未能找到合适的 Java！`。把版本设置里的「Java 版本」改成「自动选择」，或者选择启动器内置的 Java。具体见 [Java虚拟机报错](/SuperDocs/报错解决/Java虚拟机报错)。

### 模组检查没有通过

启动前的模组检查会拦截明显的冲突或缺失[前置](window:/term/前置模组)。按[弹窗](window:/term/弹窗)提示删除冲突模组或补齐前置，详见 [模组不兼容或缺少前置模组](/SuperDocs/报错解决/模组不兼容%20或%20缺少前置模组)。

## 游戏文件缺失或损坏

对应日志里的 `missing files`、`jar corruption`、`couldn't locate the game`。

常见原因：

- 下载到一半退出，依赖库或资源文件不完整。
- 手动删除了 `versions` 里的文件。
- 手机清理软件删掉了游戏文件。
- [整合包](window:/term/整合包)没有自动补全，缺少模组或配置。

处理：

1. 在版本管理里检查资源文件完整性。
2. 重新下载该版本。
3. 整合包版本确认没有关闭自动补全。
4. 确认游戏目录没有被移动。开启版本隔离时，游戏目录在 `versions/<版本>/` 下，切换隔离后原来放在 `.minecraft/mods` 的模组不会自动搬过去。

## Forge、Fabric、NeoForge 安装问题

- 安装不完整：日志里可能出现找不到启动主类、`Failed to find launch target fmlclient` 之类的报错，重新安装加载器即可。
- 重复安装 [Forge](window:/term/Forge)、[OptiFine](window:/term/OptiFine)：启动器会直接提示重复安装，需要删掉多余的一份。
- 安装器和游戏版本不匹配：例如给 1.20.1 装了 1.21 的 Forge，重新选择正确版本安装。

## 模组导致的加载失败

这类问题发生在进入主界面之前，但根源在模组：

- 模组文件被[解压](window:/term/压缩包)成了文件夹。模组应该直接放 `.jar` 文件，不要解压。
- 模组文件名含中文、空格或特殊符号。改成字母、数字、`-`、`_`、`.`。
- 同一个模组装了两份。
- 同时安装 OptiFine 和 Shaders Mod。
- 老版本模组数量太多，超出 ID 限制。
- 缺少前置模组，或模组版本与游戏版本不匹配。

逐项排查和具体案例见 [模组不兼容或缺少前置模组](/SuperDocs/报错解决/模组不兼容%20或%20缺少前置模组)。

## 存储和路径问题

- **存储空间不足**：下载、解压、补全都会失败。先清理空间。
- **访问不到游戏目录**：[Android](window:/term/Android) 11 及以上限制了 `Android/data` 的访问，部分文件管理器看不到。用 FCL 自带的文件管理，或者参考 [data 文件夹访问限制](/docs/电子小白必看/data文件夹访问限制)。
- **文件被移动或删除**：启动器记录的[路径](window:/term/路径)失效，版本会表现为「文件缺失」。

## 新版本和快照

- 26.x 的快照对启动器和 LWJGL 版本要求较高，旧版启动器可能出现 `Game version not set`、`Failed to load a library` 等问题。先更新 FCL。
- 快照本身可能不完整或有问题，换正式版对比可以快速确认。

## 处理顺序

1. 看启动停在哪个阶段。
2. 打开日志，找最后一段报错和第一个 `Caused by`。
3. 对照上面的分类定位原因。
4. 一次只改一项，改完重启验证。
5. 仍然无法解决时，导出游戏日志和启动器日志再求助，不要只发[截图](window:/term/截图)。
