图形库

图形 API一节介绍了 OpenGL / GLES / Vulkan 的概念，渲染器一节讲了如何选择。本节换个角度：逐一说明 FCL 安装包内实际打包的那些图形及相关库的来源、作用与发布形式，以便阅读安装目录中的 lib*.so。

图形转换层（渲染器核心）​

GL4ES / HolyGL4ES​

gl4es 是 ptitSeb 开发的经典转换层，将 OpenGL 1.5/2.x 调用转换为 GLES2，广泛用于树莓派、掌机与手机。FCL 使用 HolyGL4ES——AngelAuraMC（Amethyst 团队）针对 Minecraft 修复的分支，libgl4es_114.so 对应 gl4es 1.1.4 系列。其核心能力是固定管线模拟（FPE），老版本 Minecraft 使用 OpenGL 1.x 固定管线绘制，GL4ES 在 GLES2 上将其模拟实现，这也是 1.16.5 及更早版本能够运行的关键。

NG-GL4ES（Krypton Wrapper）​

NG-GL4ES 由 BZLZHH 发起、FCL 作者（ShirosakiMio）维护改进分支，同样源自 gl4es，目标是支持更复杂的着色器与更新的 MC 版本：内置 glslang + SPIRV-Cross 做着色器转换，走 GLES3 路线。FCL 通过 Gradle 将其构建为 AAR 随主 APK 发布，是当前默认渲染器。

Mesa​

Mesa 是 Linux 生态最著名的开源图形栈，FCL 使用其两部分：

  • Zink：Mesa 的 OpenGL-on-Vulkan 实现，libglxshim.so 提供桌面 GL 的 shim 层，libEGL_mesa.so 提供 EGL，支持声明 OpenGL 4.6；
  • Vulkan 驱动：Turnip（Adreno 的开源驱动，ICD 库名 libvulkan_freedreno.so）与 panvk（Mali，ICD 库名 libvulkan_panfrost.so）。这两者在 FCL 中不内置，通过驱动插件按需安装。

ANGLE​

ANGLE（Almost Native Graphics Layer Engine）是 Google 为 Chrome 开发 WebGL 而维护的底层，将 OpenGL ES 调用转换为 Vulkan（也可转 D3D/Metal）。FCL 的 jniLibs 内置 libEGL_angle.so 与 libGLESv2_angle.so，主要作为 MobileGlues 的可选第二层。Google 计划让 ANGLE 成为 Android 系统的标准 GLES 实现。

MobileGlues​

MobileGlues（名称来自 "on Mobile, GL uses ES"）是专为 Minecraft 设计的 GL 实现，运行于宿主 GLES 3.x 之上。对 MC 的适配较完善：支持 Sodium、大多数 Iris 光影以及 Create 这类自绘模组，自动完成桌面 GLSL → GLSL ES 转换，并有着色器缓存。FCL 自 2026 年 10 月起内置并深度集成其运行时配置。

virglrenderer​

virglrenderer 是虚拟化场景的 OpenGL 渲染服务（源于 QEMU/VirGL 生态）。手机启动器用它实现"OpenGL → 命令流 → 宿主 GPU"的虚拟渲染通道，对应 FCL 的 VirGL 插件渲染器（gallium_virgl，需配套 libvirgl_test_server.so，经 VTEST_SOCKET_NAME 通信）。兼容性较稳，但多一层进程间通信，性能不如直连方案。

图形之外的配套库​

SPIRV-Cross + glslang​

Khronos 官方工具链：glslang 将 GLSL 编译为 SPIR-V，SPIRV-Cross 将 SPIR-V 反编译为目标方言（如 GLSL ES）。NG-GL4ES 的着色器能力即依赖二者（游戏日志中的 DLOPEN libspirv-cross-c-shared.so 对应 SPIRV-Cross）。

OpenAL-Soft​

Minecraft 的 3D 音效走 OpenAL API，手机端由 OpenAL-Soft 实现，后端接 Android 的 OpenSL ES（启动环境中的 ALSOFT_DRIVERS=opensl）。配套包含 Google 的 oboe 低延迟音频库。

libepoxy / bhook / SDL3​

  • libepoxy：管理 OpenGL 函数指针加载，是各转换层与渲染器的公共基础设施；
  • bhook（字节跳动）：native hook 框架，FCL 用于退出码捕获与驱动替换（linkerhook 拦截 android_dlopen_ext）等底层处理；
  • SDL3：跨平台输入 / 窗口层。MC 26.3+ 改用 SDL3 处理窗口、输入与平台集成，FCL 于 2026 年 9 月集成 SDL3 绑定。

caciocavallo​

严格来说不是图形库而是 AWT 桥：将 Java AWT 的画布与字体系统映射到 Android，服务于 1.12.2 及更早的老版本（FCL 运行时目录中的 caciocavallo / caciocavallo17）。
