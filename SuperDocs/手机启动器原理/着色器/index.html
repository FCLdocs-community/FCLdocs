着色器

上一节介绍了着色器的基本概念：顶点着色器决定每个点画在哪，片段着色器决定每个点画成什么颜色。这一节讲手机场景下的着色器——着色器的转换是手机 Minecraft Java 版性能与兼容性问题的主要来源。

三种着色器语言​

着色器语言的版本众多，手机上运行的 Minecraft 主要涉及三种：

语言使用场景特点
GLSL桌面 OpenGL#version 330，功能完整
GLSL ES移动端 OpenGL ES需显式声明 precision，部分特性被裁剪
SPIR-VVulkan编译后的中间码，非文本格式

桌面 Minecraft 向 GPU 提交的是桌面 GLSL，而手机 GPU 只接受 GLSL ES 或 SPIR-V，需要由渲染器完成转换：

桌面 GLSL（Minecraft + 光影包） ──→ 渲染器转换 ──→ GLSL ES / SPIR-V ──→ 手机 GPU

各渲染器的转换方式​

GL4ES​

GL4ES 将 OpenGL 转换为 GLES2，着色器转换能力有限。其上游 README 明确说明"只有简单着色器能正常工作"。因此它能稳定运行原版及简单模组，但无法承载复杂光影——这也是它兼容版本上限不高（1.21.4）的原因。

NG-GL4ES（Krypton Wrapper）​

NG-GL4ES 是 gl4es 的深度改进分支，针对着色器做了专门增强：

  • 内置 glslang（Khronos 官方编译器前端），将桌面 GLSL 编译为中间表示；
  • 使用 SPIRV-Cross 反向输出为 GLSL ES 3.0。

这两步对应游戏日志中的 DLOPEN libspirv-cross-c-shared.so。整体转换能力显著高于 GL4ES，兼容版本上限可到 26.2。

Zink（Mesa）​

Zink 是 Mesa 的 OpenGL-on-Vulkan 实现，着色器转换质量高：OpenGL → Mesa 中间码（NIR）→ 具体 GPU 指令集，并支持着色器缓存。FCL 为其设置的关键环境变量（FCLauncher.addRendererEnvInner()）：

MESA_GL_VERSION_OVERRIDE=4.6      ← 向游戏声明 OpenGL 4.6 支持
MESA_GLSL_VERSION_OVERRIDE=460    ← 按桌面 GLSL 4.60 编译
MESA_GLSL_CACHE_DIR=<缓存目录>     ← 着色器缓存，二次启动明显加快

MobileGlues​

MobileGlues 是专为 Minecraft 设计的 GL 实现，对着色器转换做了大量自动化处理：

  • 自动将桌面 GLSL 转为 GLSL ES，处理 layout(binding)、版本指令，并补齐 precision 声明；
  • 向着色器注入 MG_MOBILEGLUES 宏，供光影作者做针对性适配；
  • 内置着色器缓存（FCL 设置中的 maxGlslCacheSize），加快光影包重载；
  • 可选叠加 ANGLE（将 ES 转为 Vulkan），构成两层转换链。

ANGLE​

ANGLE 是 Chrome 的 WebGL 后端，将 OpenGL ES 调用整体转换为 Vulkan（着色器变为 SPIR-V）。它一般不作为独立渲染器，而是在 FCL 中作为 MobileGlues 等的可选第二层，用于提升兼容性与稳定性。

为什么手机上跑光影困难​

光影包（通过 Iris/OptiFine 加载）会给转换链带来三类压力：

  1. 着色器复杂度：光影包含数百个着色器，且大量使用 compute shader（计算着色器）处理阴影、泛光，转换链每道都可能丢失特性，导致个别光影白屏或花屏（各渲染器的兼容列表不同）；
  2. 转换损耗：桌面 GLSL 自动转 GLSL ES/SPIR-V 并不总是完整，兼容性依赖渲染器的成熟度；
  3. 重复编译开销：切换维度、切换光影都要重新编译着色器，没有缓存时会明显卡顿——这是着色器缓存（MobileGlues、Zink）价值所在。

此外，光影本身渲染目标切换频繁，会放大手机 GPU 带宽与填充率的不足。

总体结论：中高端芯片配合 Zink 或 MobileGlues 可以运行中轻度光影；重度 PBR 光影在手机上属于极限负载。

26.x 版本渲染改版的影响​

26.x 系列对渲染层做了较大改动，与着色器相关的关键节点如下：

  • 26.1：改用新的版本号格式，并完全移除代码混淆；
  • 26.2：加入 Vulkan 渲染后端（实验性），可在图形设置中在"默认 / 优先使用 Vulkan（实验性）/ 优先使用 OpenGL"间切换；不支持 Vulkan 的硬件回退到 OpenGL；需要设备支持 Vulkan 1.2 及以上；macOS 上经 MoltenVK 转换。这也意味着桌面 GLSL 不再是唯一输入路径，着色器可直接以 SPIR-V 形式执行；
  • 26.3：改用 SDL3 而非 GLFW 处理窗口管理、输入与平台集成；着色器改由 ShaderC 编译（即使使用 OpenGL 后端），引入顺序无关透明（OIT）算法，地形渲染在支持的设备上改用 MultiDrawIndirect。

这些改动让新版本在手机上主要依赖 Zink / MobileGlues（配合 SDL3 与 LWJGL 3.4.1）运行，而 GL4ES/VGPU 系渲染器无法覆盖 26.x。

参考仓库：NG-GL4ES 、 MobileGlues-release 、 ANGLE 、 Mesa ；版本信息见 Java版26.2 与 Java版26.3
