Java虚拟机报错

Java 虚拟机（JVM）报错，指的是异常类型以 java.lang. 开头、由 JVM 或 Java 运行时直接抛出的错误。它和模组报错、渲染器报错要分开看：

  • JVM 报错：UnsupportedClassVersionError、OutOfMemoryError、UnsatisfiedLinkError 等。
  • 游戏或模组报错：NoClassDefFoundError、NoSuchMethodError、各类模组加载异常，通常去 游戏加载错误 或 模组不兼容或缺少前置模组 排查。
  • 图形库报错：GL_、Vulkan、EGL 相关，见 Vulkan报错。

先确认 Java 版本​

版本设置里有「Java 版本」，默认是「自动选择」。FCL 内置 Java 8、17、21、25，会根据版本要求自动挑选。

手动选择时的对应关系：

游戏版本需要的 Java
1.16.5 及以下Java 8
1.17 – 1.20.4Java 17
1.20.5 – 1.21.xJava 21
26.1 及以后Java 25

如果手动选的 Java 和版本要求不一致，启动器会弹「你正在使用不推荐的 Java 版本」，可以选择「自动选择」纠正。

如果提示「未能找到合适的 Java！」，说明启动器里没有可用的运行时。改用自动选择，或者重新安装内置 Java，不要随便导入电脑上的 JRE。

UnsupportedClassVersionError​

典型日志：

java.lang.UnsupportedClassVersionError: com/example/ExampleMod has been compiled
by a more recent version of the Java Runtime (class file version 69.0),
this version of the Java Runtime only recognizes class file versions up to 65.0

class file version 和 Java 版本的对应关系：

class file versionJava 版本
528
5511
6117
6521
6925

这条报错的意思是：代码是用更高的 Java 编译的，当前 Java 太旧。

常见原因：

  • 游戏版本要求 Java 25，但手动选了 21 或 17。
  • 模组是用更高 Java 编译的，游戏自带的 Java 跟不上。
  • 旧版 Forge 配了过新的 Java，或新版 Forge 配了 Java 8。

处理：

  1. Java 版本改为「自动选择」。
  2. 26.x 版本确认使用 Java 25。
  3. 模组报这个错时，更新模组，或删除要求更高 Java 的模组。
  4. 旧版 Forge 反而需要 Java 8，不要一律选最高版本。

有时日志里是 Unsupported class file major version 69，出现在模组加载器或 ASM 里，本质相同，按上面处理。

内存不足​

Java heap space​

典型日志：

java.lang.OutOfMemoryError: Java heap space

意思是堆内存不够。常见于大型整合包、光影、高视距、模组过多。

处理：

  1. 在全局游戏设置或版本设置里调大「游戏内存」。
  2. 一次加 256–512 MB，不要直接拉满。
  3. 同时降低视距、关闭光影、减少常驻模组。

GC overhead limit exceeded​

java.lang.OutOfMemoryError: GC overhead limit exceeded

垃圾回收占用了过多时间，实际可用内存太少。处理方式和 Java heap space 相同。

Metaspace​

java.lang.OutOfMemoryError: Metaspace

类元数据区（Metaspace）不足，通常是模组太多、类加载量太大。减少模组，或换用更新的 Java 运行时。

unable to create native thread​

java.lang.OutOfMemoryError: unable to create native thread

线程或系统资源耗尽。关闭后台应用、减少模组、重启设备再试。

内存不是越大越好​

分配过大会出现另一类错误：

Could not reserve enough space for object heap
Invalid maximum heap size

FCL 也会提示「当前游戏因为分配的内存过大，无法继续运行」或「超过了 32 位 Java 内存限制」。

处理：降低分配值。不要超过设备实际可用内存，自动分配通常比手动拉满更稳。

本地库缺失​

典型日志：

java.lang.UnsatisfiedLinkError: dlopen failed: library "libawt_xawt.so" not found
java.lang.UnsatisfiedLinkError: libfreetype.so.6: cannot open shared object file

FCL 的提示是「当前游戏因为缺少本地库：xxx，无法继续运行」。

常见原因：

  • 手动导入了不完整的 Java 运行时。
  • 导入了电脑上的 JRE，架构或依赖不匹配。
  • 压缩包解压层级不对，lib 目录结构不正确。
  • 运行时文件被杀毒软件或清理软件删除。

处理：

  1. 优先使用启动器内置的 Java。
  2. 删除损坏的自定义 Java，重新安装或重新导入。
  3. 导入时确认是 Android 可用的 arm64 运行时，并且目录结构完整。
  4. 不要直接把电脑上的 JRE 复制进手机。

VM 初始化失败和主类问题​

典型日志：

Error occurred during initialization of VM
Error: Could not find or load main class ...

或者直接提示找不到 libjvm.so、OpenJDK exited with code : 1。

  • Error occurred during initialization of VM：Java 运行时损坏或参数不合法。重装 Java，检查自定义 JVM 参数。
  • Could not find or load main class：主类或 classpath 有问题，不是 JVM 本身的问题，按 游戏加载错误 检查版本文件。
  • OpenJDK exited with code : 1：只说明进程退出，具体原因要往上找异常。

JVM 原生崩溃​

典型日志：

# A fatal error has been detected by the Java Runtime Environment:
#  SIGSEGV (0xb) ...
# Problematic frame:
# C  [libOSMesa_8.so+0x4ced18]  OSMesaMakeCurrent+0x6c

同时会生成 hs_err_pid<数字>.log。

这类不是普通 Java 配置错误，而是 JVM 在原生代码里崩溃。重点看 Problematic frame：

  • 出现在 libOSMesa、libGL、libEGL、libvulkan 等图形库：渲染器或驱动问题。
  • 出现在某个模组的本地库：该模组的原生部分有问题。
  • 出现在 libjvm.so、libart.so：Java 运行时或系统环境问题。

处理顺序：换渲染器、换驱动、更新启动器；如果和 Vulkan 有关，看 Vulkan报错。内存不足和 Java 版本通常不会以 SIGSEGV 的形式出现。

Forge 和 Java 版本冲突​

FCL 的提示：

当前游戏因为您所使用的 Forge 版本与当前使用的 Java 冲突崩溃，请尝试更新 Forge。

老版本 Forge 需要 Java 8，新版本需要 Java 17、21 或 25。版本选错时，Forge 会在启动阶段直接崩溃。

处理：按游戏版本选择 Java，或者更新 Forge。不要为了「用新 Java」强行给老 Forge 配高版本 Java。

排查顺序​

  1. 先看异常类名和第一个 Caused by。
  2. 确认 Java 版本是否匹配，优先用自动选择。
  3. 内存问题先调分配值，再减模组和光影。
  4. 出现 UnsatisfiedLinkError 先怀疑 Java 运行时，不要先改游戏文件。
  5. 出现 hs_err_pid 先看 Problematic frame，按图形库或原生库分类。
  6. 还无法判断时，导出 latest_game.log 和启动器日志一起求助。
