Vulkan报错

Minecraft 从 26.2 开始提供 Vulkan 渲染后端。它和以前的 OpenGL 是两条独立的路：OpenGL 走渲染器转换层，Vulkan 直接和设备的 Vulkan 驱动打交道。

大部分「Vulkan报错」并不是启动器坏了，而是设备能力不够、驱动没生效，或者选错了后端。

三个容易混淆的概念​

  • 图形后端：版本设置 → 渲染组里的「图形后端」，可选 default、opengl、vulkan。只对 26.2 及以后版本生效，决定游戏走哪条渲染路径。这些选项和全局游戏设置里的渲染项是同一套。
  • 渲染器：Holy-GL4ES、Zink、MobileGlues 等，负责把 OpenGL 转成手机能用的接口。游戏走 OpenGL 时才用到。
  • Vulkan 驱动：系统驱动，或通过驱动插件加载的自定义驱动（默认 Turnip）。只有走 Vulkan 时才用到。

三者互相独立。渲染器能跑，不代表 Vulkan 后端能跑；换了 Vulkan 驱动，也不会改变 OpenGL 渲染器的选择。

哪些版本有 Vulkan​

只有 26.2 及以后版本带 Vulkan 后端。26.1、1.21.x 及更早版本没有这个选项，「图形后端」对它们不起作用。

26.2 和 26.3 的要求也不完全一样，检测工具会按版本区间分别判断。

26.2+ 的硬性要求​

基础要求是 Vulkan 1.2 及以上。

26.2 起需要这些扩展：

  • VK_KHR_dynamic_rendering（仅 26.2–26.3 要求）
  • VK_KHR_push_descriptor（仅 26.2–26.3 要求）
  • VK_KHR_synchronization2
  • VK_EXT_vertex_attribute_divisor
  • VK_KHR_swapchain

还需要这些特性：

  • multiDrawIndirect
  • fillModeNonSolid（26.2 必需，26.3 起改为可选）
  • samplerAnisotropy
  • shaderDrawParameters
  • timelineSemaphore
  • hostQueryReset
  • synchronization2
  • dynamicRendering（仅 26.2–26.3 要求）
  • vertexAttributeInstanceRateDivisor
  • drawIndirectFirstInstance（26.3 起要求）

FCL 的 vkshim 兼容层可以补一部分缺口：

  • 设备只有 VK_KHR_vertex_attribute_divisor 时，可以合成 VK_EXT_vertex_attribute_divisor。
  • 缺少 fillModeNonSolid 时，可以模拟开启，代价是线框渲染退化成实心。

兼容层只作用于系统 Vulkan 加载器路径。自定义驱动本身缺能力时，仍然会失败。

先用检测工具​

版本设置 → 渲染组 → 「检测 Vulkan」：

  • 未检测时显示「未检测」，检测后显示 Vulkan 版本号。
  • 结果会列出总体结论、各版本区间是否支持、Vulkan 版本、实际生效的驱动。
  • 扩展和特性逐项列出，缺失的标红，并标注「必需」或「可选」的版本区间。
  • 检测结果会缓存。驱动状态变化或检测规则更新后需要重新检测。

启动 26.2 及以后版本时，FCL 也会在启动前检查一次：

  • 有缓存且支持，直接启动。
  • 没有缓存，询问是否立即检测，可以跳过。
  • 不满足要求，会列出缺失项并警告，但仍然允许点「仍要启动」。

注意：这个检查只看游戏版本，和你选 OpenGL 还是 Vulkan 无关。即使打算用 OpenGL，也可能看到检测提示。不需要的话，可以打开「禁用 Vulkan 兼容性检测」。

日志里常见的关键句​

  • Device [xxx] does not support Vulkan 1.2 设备报告的 Vulkan 版本低于 1.2，或者驱动没有正确加载。
  • Failed to create backend Vulkan 游戏创建 Vulkan 后端失败，通常紧跟着具体原因。
  • com.mojang.blaze3d.systems.BackendCreationException: Device missing capabilities 设备缺少必需的扩展或特性。看检测结果里标红的项。
  • VK_ERROR_INCOMPATIBLE_DRIVER 驱动和 Vulkan 加载器不兼容，常见于驱动插件装错或版本不匹配。
  • VK_ERROR_EXTENSION_NOT_PRESENT 缺少扩展，和检测结果里的扩展缺失对应。
  • VK_ERROR_DEVICE_LOST 设备或驱动崩溃、过热、超频，图形上下文丢失。
  • Failed to load a library LWJGL 或本地库加载失败，先更新启动器，再检查驱动插件。

按情况处理​

提示不支持 Vulkan 1.2​

  1. 确认没有勾选「使用系统 Vulkan 驱动」以外的错误组合。默认使用自定义驱动，驱动名通常是 Turnip。
  2. 打开「检测 Vulkan」，看结果里的驱动是系统驱动还是自定义驱动。如果请求了自定义驱动但显示系统驱动，说明驱动加载失败并回落了。
  3. 重新安装与设备 GPU 匹配的驱动插件。Adreno 常用 Turnip，Mali 可以尝试 PanVK 一类的社区驱动。
  4. 如果系统驱动本身只有 Vulkan 1.1，换自定义驱动是主要办法。

缺少扩展或特性​

  1. 在检测结果里看具体缺哪一项。
  2. 优先换驱动，驱动版本越新，支持越完整。
  3. 确认 FCL 版本足够新。旧版本没有 vkshim 补齐，也没有 26.3、26.4 的新依赖判断。
  4. 缺 fillModeNonSolid 且无法补齐时，只能换驱动或回退 OpenGL。

驱动看起来装了但没用上​

  • 检测结果里的「驱动」显示的是实际生效的驱动，不是你以为的那个。
  • 自定义驱动需要插件支持，架构不匹配（32 位设备装 64 位驱动）会直接加载失败。
  • 部分设备需要关闭「使用系统 Vulkan 驱动」才会走自定义驱动。

DEVICE_LOST 或游戏中途花屏退出​

  • 先重启游戏。反复出现时重启设备。
  • 关闭超频、降低画质，避免过热。
  • 换一个驱动版本，或改用系统驱动对比。
  • 如果只在 Vulkan 下出现，基本可以确定是驱动问题。

加载库失败​

  • 更新 FCL，旧版本可能缺少新版 LWJGL 的 Vulkan 本地库。
  • 确认驱动插件和启动器版本匹配。
  • 仍然失败时，先回退 OpenGL，确认游戏本身能正常运行。

回退到 OpenGL​

设备确实不支持，或者暂时不想折腾驱动时：

  1. 版本设置 → 图形后端，改成 opengl。想留给游戏自己决定就选 default。
  2. 渲染器继续用原来的 Holy-GL4ES、Zink、MobileGlues 等。
  3. 更老的版本没有 Vulkan 选项，本来就走 OpenGL。

回退 OpenGL 后，Vulkan 检测仍然可能提示，直接忽略或关闭检测即可。

不要混淆的几件事​

  • Zink 能跑不等于 Vulkan 后端能跑。Zink 是用 Vulkan 来跑 OpenGL，游戏仍然认为自己在用 OpenGL，要求比原生 Vulkan 后端低。
  • 检测不满足但游戏正常：如果你用的是 OpenGL，检测结果只代表「不能走 Vulkan」，不影响当前玩法。
  • 26.3 及以后渲染器版本不兼容：部分旧版 MobileGlues 在 26.3+ 会无法进入世界，这属于渲染器选择错误，不是 Vulkan 检测问题。换新版渲染器，或改用其他渲染器。
  • Vulkan 后端和 Vulkan 驱动插件：后端决定游戏用不用 Vulkan，驱动插件决定 Vulkan 由谁来提供。两者都正确，才能跑起来。

排查顺序​

  1. 先跑「检测 Vulkan」，不要凭感觉换设置。
  2. 看缺失的是版本、扩展、特性还是驱动。
  3. 换驱动或换系统驱动对比，一次只改一项。
  4. 检查日志里的 BackendCreationException 和 VK_ERROR_ 具体行。
  5. 确认不是渲染器问题后，再决定继续修 Vulkan 还是回退 OpenGL。
  6. 求助时导出游戏日志，并附上检测结果截图。
