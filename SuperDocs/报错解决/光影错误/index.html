光影错误

光影问题基本来自三部分：光影加载器、光影包本身、以及手机上的渲染器和驱动。三者任意一个不匹配，都可能表现为聊天框报错、白屏、全虚空、花屏或直接崩溃。

FCL 不实现光影，也不负责修复某个具体光影包。FCL 只提供 OpenGL 环境和渲染器；光影能不能跑，取决于加载器、渲染器和驱动的组合。上游维护者的态度也很明确：这类问题通常需要换渲染器或更新驱动，而不是等启动器修。

先分清三个光影加载器​

加载器模组加载器依赖说明
IrisFabric / NeoForgeSodium现代版本的主流选择，兼容大多数 OptiFine 光影包
OculusForgeRubidium（1.20.1 分支改用 Embeddium）Iris 的 Forge 移植，官方声明永远不兼容 OptiFine
OptiFine独立安装，可搭配 Forge无自带光影功能，更新较慢，与 Iris、Oculus、Sodium 都不兼容

几个硬性规则：

  • 只装一个光影加载器。OptiFine 和 Iris 同时装、OptiFine 和 Oculus 同时装，都会冲突。
  • Iris 必须搭配 Sodium，否则可能启动失败或渲染异常。
  • Oculus 必须搭配对应版本的 Rubidium 或 Embeddium，缺依赖时通常不是光影报错，而是启动阶段直接崩溃。
  • 光影包要和加载器、游戏版本对应。给 1.20.1 准备的光影包，不保证能在 1.21 或 26.x 上编译。

手机上的实际情况​

Iris 官方文档把移动端（PojavLauncher 等）列为「不支持」，意思是官方不测试、不保证、也不处理移动端问题，并不是说在手机上绝对跑不起来。

实际测试中，用 MobileGlues 加载 Iris 可以正常进入游戏并加载部分光影，只是并非所有光影包都能工作。Zink 配合较好的 Vulkan 驱动也能跑一部分。能不能成，取决于渲染器对光影所用 GLSL 特性的转换能力。

光影对图形能力的要求比原版高：

  • Minecraft 本身要求 OpenGL 3.3。
  • Sodium 官方支持的是 OpenGL 4.5 及以上的驱动。
  • 含几何着色器的光影需要 OpenGL 3.2 及以上。
  • 含计算着色器的光影需要 GLSL 430，也就是 OpenGL 4.3 及以上。

GL4ES 只到 GLES2，复杂光影基本跑不了；Krypton Wrapper（NG-GL4ES）通过 glslang 和 SPIRV-Cross 提升了一截，但仍然有转换损耗；MobileGlues 和 Zink 的能力更强，是尝试光影的首选。各渲染器的差异见渲染器和着色器。

报错在哪看​

光影错误经常只出现在聊天框里，容易被忽略。除了截图聊天框，还可以看日志：

  • 游戏日志：/sdcard/FCL/log/latest_game.log
  • 游戏内：菜单 → 设置 → 「显示日志」
  • 搜索关键词：Iris、Oculus、OptiFine、Shaders、shader、GLSL、compilation、Failed to load

Iris 和 Oculus 的日志文案基本一致，常见的几类：

Failed to load the shaderpack "<名称>"!
Failed to load the shaderpack "<名称>" because it does not exist in your shaderpacks folder!
Failed to load the shaderpack "<名称>" because it contains invalid characters in its path
The shaderpack "<名称>" appears to be corrupted, please try downloading it again!
Could not load the shaderpack "<名称>" because it appears to lack a "shaders" directory
Pack "<名称>" is not valid! Can't load it.
Shader compilation failed for <程序名>!
Shader compilation log for <程序名>: <编译日志>
Shader storage buffers/immutable buffer storage is not supported on this graphics card
Image units are not supported on this platform
Falling back to normal rendering without shaders because the shaderpack could not be loaded

OptiFine 的报错通常直接显示在聊天框，带 Shaders 或 OptiFine 前缀，同时写入日志。看到编译失败时，重点不是背报错，而是判断是「包的问题」还是「图形环境不支持」。

按现象处理​

光影列表里选了，但没有效果​

  1. 确认选中的光影包还在 shaderpacks 目录里，没有被删除或改名。
  2. 重新下载光影包。日志出现 corrupted 或 not valid 时，基本是压缩包损坏。
  3. 检查压缩包结构。光影包根目录必须直接有 shaders 文件夹，不能是「压缩包里面再套一层文件夹」。
  4. 确认光影包支持当前游戏版本和加载器。

一进世界就白屏、全虚空或黑屏​

这类通常不是光影包坏了，而是渲染器没能正确转换光影的着色器。典型情况是画面全是虚空、方块贴图异常、地形变黑。

处理顺序：

  1. 换成 MobileGlues 再试，必要时叠加 ANGLE。
  2. 有条件和驱动插件时，试 Zink + Turnip。
  3. 降低光影画质，关闭计算着色器相关的特效。
  4. 换一个较轻的光影包（例如 BSL、Complementary）做对比。轻量包能跑、重包不行，说明是性能或特性不足，不是安装错误。

聊天框提示编译失败​

看到 Shader compilation failed 或 GLSL 编译错误时：

  1. 确认当前渲染器不是 GL4ES。GL4ES 的 GLES2 能力不足，复杂光影必然失败。
  2. 换 MobileGlues 或 Zink，再重新加载光影。
  3. 更新渲染器和 Vulkan 驱动。部分编译错误是驱动 bug，换驱动版本可能直接消失。
  4. 换光影包版本。同一个光影的新版本可能用了更多特性，旧版本反而能跑。
  5. 仍然失败时，这属于上游渲染器或驱动的转换限制，换包比继续修更快。

日志提示缺少 storage buffer、image unit 等特性​

Shader storage buffers/immutable buffer storage is not supported on this graphics card
Image units are not supported on this platform

意思是当前图形环境没有提供光影需要的 OpenGL 特性。GL4ES 和部分老渲染器不会有这些能力。换 MobileGlues 或 Zink，或者换一个不使用这些特性的光影包。

玩几分钟后崩溃、掉帧、过热​

这类不是光影安装错误，而是设备负载过高。手机 GPU 在光影下的功耗和发热远高于原版，长时间运行可能触发降频、驱动崩溃或系统杀进程。

可以尝试：

  • 降低光影画质和分辨率。
  • 降低视距、关闭高开销特效。
  • 关闭其他后台应用，避免边充电边玩。
  • 换更轻的光影包。

如果日志里出现驱动或渲染器相关的崩溃，按渲染器选择错误和 Vulkan报错继续排查。

装了光影模组后游戏启动不了​

先确认不是光影本身的问题：

  1. 检查加载器和游戏版本是否匹配，Iris、Oculus、OptiFine 是否只装了一个。
  2. Iris 是否装了 Sodium，Oculus 是否装了 Rubidium 或 Embeddium。
  3. 删除光影模组，确认游戏能正常启动；能启动说明问题在光影侧。
  4. 重新安装对应版本的光影加载器，不要混用不同版本。

光影和 OptiFine 冲突​

  • Iris 与 OptiFine 不兼容。
  • Oculus 官方声明永远不兼容 OptiFine。
  • OptiFine 与 Sodium 也不兼容。

需要 OptiFine 的其他功能时，不要在 Iris 环境里再装 OptiFine，改用对应的替代模组。需要光影时，优先保留 Iris 或 Oculus。

光影管理​

FCL 的管理页提供光影管理，可以导入、重命名和删除光影包。光影包实际放在游戏目录的 shaderpacks 文件夹里，手动放入也能识别。

加载失败时，可以先把 shaderpacks 里的包移走，进入游戏关闭光影，再把包放回来逐个测试。Iris 默认按 K 可以快速开关光影，方便对比。

排查顺序​

  1. 确认加载器、游戏版本、模组加载器三者匹配，只装一个光影加载器。
  2. 确认依赖齐全：Iris 要 Sodium，Oculus 要 Rubidium 或 Embeddium。
  3. 看聊天框和日志里的关键句，区分「加载失败」「编译失败」「运行崩溃」。
  4. 换渲染器：优先 MobileGlues，其次 Zink；GL4ES 不适合复杂光影。
  5. 用轻量光影做对照，判断是包的问题还是环境的问题。
  6. 换包、换驱动版本。仍然不行时，记录日志和光影名称，向渲染器或光影作者反馈。
