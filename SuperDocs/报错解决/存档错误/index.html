存档错误

存档问题大致分四类：版本不兼容、内容丢失或地形异常、模组或数据包被移除、文件损坏或被锁定。

不管属于哪一类，第一步都一样：先备份，再操作。

先备份，再操作​

  • 关闭游戏，确认没有后台进程正在写存档。
  • 在 FCL 的管理页 → 世界/数据包中导出世界，或者直接复制整个存档文件夹。
  • 之后的修复、测试都针对副本进行，不要在原存档上反复尝试。

存档位置和版本隔离有关：

  • 开启版本隔离（默认）：.minecraft/versions/<版本>/saves/<世界>
  • 关闭版本隔离：.minecraft/saves/<世界>

切换版本隔离后，世界看起来「消失」，通常只是换到了另一个目录，并没有被删除。两个位置都找一遍，再用「添加世界」导入。

版本不兼容​

每个存档都记录着自己的数据版本：

  • level.dat 里保存着整个存档的数据版本。
  • 每个区块里也保存着该区块最后一次加载时的数据版本。
  • 区块数据存在 region/r.<X>.<Z>.mca 里，一个区域文件包含 32×32 个区块。

新版 Minecraft 可以读取并升级旧存档，但旧版本读取新存档不受支持。

用旧版本打开新版本的存档时，通常会出现版本不匹配的提示。继续进入后可能出现：

  • 新版本的方块、物品、实体无法识别，变成空气、石头或消失。
  • 新版本的地形、生物群系无法读取，区块被重新生成，表现为地形出现空洞、断层，甚至变成平地。
  • 自定义维度、结构、配方等内容丢失。
  • 存档直接崩溃或无法加载。

更麻烦的是：旧版本一旦重新保存这个存档，新版本写入的内容可能被永久丢弃，再换回新版本也找不回来。

处理原则：

  1. 用保存过该存档的版本，或者更新的版本打开。
  2. 不要在新旧版本之间反复切换并保存。
  3. 已经出现内容丢失时，优先恢复备份，不要继续在损坏的存档上探索。
  4. 从旧版本升级到新版本通常是安全的，但模组和数据包必须一起升级。

内容丢失和地形变平​

存档「进去之后东西全没了」「地形变成平地」，常见原因不只有降级：

  • 用旧版本打开新版本存档，新内容无法识别。
  • 模组被删除或替换，模组添加的方块、物品、生物群系无法读取。
  • 数据包被删除，数据包添加的维度、生物群系、结构消失。
  • 区块文件损坏或缺失，游戏按新地形重新生成。
  • 导入存档时文件不完整，只带进来了 level.dat，缺少 region。

已经丢失的区块和内容，没有备份基本无法原样恢复。可以尝试：

  1. 恢复备份，或者恢复原来的模组和数据包组合。
  2. 把缺失的模组、数据包装回相同版本，再打开一次。
  3. 用 Amulet、MCEdit 等第三方工具删除无法识别的方块或实体，让存档至少能进入。
  4. 如果只是个别区块损坏，可以删除对应的区域文件让游戏重新生成，但这会永久丢失该区域的内容。

模组或数据包被删除​

模组​

删掉模组后，存档里由该模组添加的方块、物品、维度、实体都会失去定义。表现可能是：

  • 加载世界时崩溃，日志里出现缺少注册项、未知方块、未知物品之类的信息。
  • 进入世界后发现方块消失、箱子里的物品消失、生物不见。
  • 自定义维度无法进入，传送门失效。

处理：

  1. 把被删除的模组装回相同版本，这是最稳妥的办法。
  2. 如果确实不想要该模组，先备份存档，再考虑用工具清理相关内容。
  3. 不要用「更新到另一个版本」的模组去打开旧存档，注册名和数据结构可能已经变了。

数据包​

数据包影响世界生成、维度、生物群系、配方、进度等内容。删除数据包后可能出现：

  • 世界加载失败，提示数据包错误。
  • 自定义维度无法进入。
  • 结构、生物群系、配方丢失或变化。

数据包出错时，游戏会给出处理选项：

  • JSON 语法错误会显示「安全错误」提示，要求修复或移除数据包。
  • 数据包导致世界无法加载时，游戏会提供「安全模式」加载，只加载默认数据包，方便你进入世界后移除有问题的数据包。
  • 使用了实验性内容的数据包，会弹出实验性设置警告，需要确认启用对应实验项才能加载。

注意：安全模式只处理数据包，不会禁用模组。模组导致的问题仍然需要手动删除模组。

文件损坏​

level.dat​

level.dat 是存档的核心文件。目录里没有 level.dat 或 level.dat_old 时，启动器不会把它识别为存档。

游戏保存 level.dat 时会自动保留一份 level.dat_old。主文件损坏时，游戏会尝试自动恢复：

  • 把损坏的主文件改名为 level.dat_corrupted_<时间戳>。
  • 用 level.dat_old 恢复成 level.dat。

如果自动恢复也失败，可以手动把 level.dat_old 复制成 level.dat 再试。前提是 level.dat_old 本身没有损坏。

区块和区域文件​

常见日志：

Chunk file at <坐标> is missing
Chunk file at <坐标> is in the wrong location; relocating
Region file <文件> is corrupt
Failed to read chunk

含义是某个区块或区域文件读不出来。处理顺序：

  1. 恢复备份。
  2. 用存档修复工具扫描并修复区域文件。
  3. 最后手段才是删除对应的 r.<X>.<Z>.mca，让游戏重新生成该区域。这会丢失该区域内的建筑和地形。

不要在游戏运行时用清理软件整理存档目录，也不要手动编辑 .mca 文件。

导入和导出​

FCL 导入世界时支持两种压缩包结构：

  • level.dat 直接位于压缩包根目录。
  • 压缩包里只有一个世界文件夹，level.dat 在该文件夹内。

报错含义：

  • 无法识别该存档压缩包：压缩包里找不到 level.dat，或者层级不对。
  • 此世界已经存在：目标目录里已有同名世界，先改名或删除旧副本。
  • 无法导入此世界：压缩包损坏、空间不足或路径非法。

导出前先关闭游戏，避免把正在写入的文件打进压缩包。

世界被锁定​

FCL 删除或复制世界时提示「该世界已被游戏或其他启动器锁定」，说明存档目录里的 session.lock 仍被占用。

处理：

  1. 完全退出游戏，不要只切到后台。
  2. 关闭其他正在使用同一存档的启动器或实例。
  3. 强制停止 FCL 后重新打开。
  4. 再执行删除、复制或导入。

不要在游戏运行时删除 session.lock，也不要同时开两个实例读写同一个世界。

什么时候该放弃修复​

出现以下情况时，继续操作的风险很高：

  • 存档已经被旧版本重新保存过，新内容大面积丢失。
  • 区域文件大面积损坏，且没有备份。
  • 模组和数据包已经无法找回原版本。

这时优先保留现有文件作为证据或纪念，不要继续让游戏反复加载和保存，避免损坏范围扩大。

排查顺序​

  1. 关闭游戏，备份整个存档。
  2. 确认存档所在目录，排除版本隔离导致的「世界消失」。
  3. 回忆最后一次正常打开用的是哪个版本、哪些模组和数据包，尽量还原。
  4. 看日志里是版本、注册项、数据包还是区块文件的问题。
  5. 先在副本上修复和测试，确认能进入后再替换原存档。
  6. 无法判断时，保留 latest_game.log 和存档副本再求助。
