**本教程面向的是：已经下载好游戏版本，但尚未安装模组加载器的玩家。**

# 3. 自动安装 (核心与模组加载器)

在完成“游戏设置”与“版本下载”后，当前游戏仍处于纯粹的“原版”状态。此时需要进入 `自动安装` 界面，为当前选中的游戏版本安装对应的 **模组加载器（API）** 以及相关的性能/视觉优化组件。

> 🛑 **模组冲突警告**：绝大多数 Minecraft 整合包**只能使用一种加载器（API）**。一个游戏版本无法同时共存 Forge 和 Fabric。如需切换，需卸载原加载器或使用“版本隔离”功能。

---

## 3.1 主流模组加载器 API 解析

FCL 原生支持当前模组生态中最主流的四大加载器，其选择通常取决于目标游戏版本及玩家期望的模组环境：

*   **Forge**：
    *   **历史地位**：Minecraft 模组圈的元老级 API，拥有超过 10 年的历史深度。在 1.16.5 及之前的低中版本中占据绝对统治地位。
    *   **技术特征**：具备独立、庞大的事件总线系统，支持极其复杂的游戏机制（如大型科技、魔法模组）。
    *   **应用场景**：绝大多数基于 1.12.2 - 1.16.5 开发的经典大型整合包均依赖此 API。启动速度相对较慢，内存占用较高。

*   **NeoForge**：
    *   **历史地位**：由原 Forge 核心团队分裂后重新建立的**现代化 Forge 接替者**。
    *   **技术特征**：对遗留底层代码进行了全面重构，启动速度与多线程优化相比原版 Forge 有了质的飞跃。
    *   **应用场景**：**强烈推荐在 1.20.1 及更高版本的高版本游戏**中选用 NeoForge，它目前已成为高版本大型整合包的首选环境。

*   **Fabric**：
    *   **历史地位**：在 1.14 时代崛起的轻量级加载器，走“小而美”路线。
    *   **技术特征**：底层采用模块化设计与 `Mixin` 代码注入技术，加载极速，系统极其轻量。
    *   **应用场景**：完美契合**功能性小模组（如小地图、物品栏整理）**以及**现代性能优化模组（Sodium 等）**。现代服务器的生存/小游戏模组包几乎均基于 Fabric 构建。

*   **Quilt**：
    *   **历史地位**：Fabric 分支的衍生加载器。
    *   **技术特征**：在 Fabric 基础上进一步优化了 API 构建规范，旨在解决部分 Fabric 原生的底层冲突。
    *   **应用场景**：目前模组生态的丰富度仍略逊于 Fabric。若追求最宽泛的模组兼容性，Fabric仍是首选。

> 💡 **选型建议总结**：若游玩的是“原版增强”（无大改，仅加小功能），优选 **Fabric**；若游玩的是“大型内容包”（增加新维度、新系统），低版本选 **Forge**，高版本（1.20+）选 **NeoForge**。

## 3.2 性能与视觉优化方案 (OptiFine vs 现代方案)

*   **OptiFine**（传统方案）：
    *   **功能**：老牌的性能与光影支持优化模组，能大幅提升游戏基础帧率，支持加载传统光影包。
    *   **操作**：若界面中该项目右侧显示 `->` 箭头，点击即可下载并安装。
    *   ⚠️ **高危警告**：OptiFine 早期代码与许多现代 Mod 存在严重的**底层代码冲突**。在现代模组环境中极易导致游戏崩溃，**强烈不建议在玩家游玩大型整合包时安装 OptiFine**。

*   **Sodium + Iris**（主流现代化方案）：
    *   **地位**：目前综合表现最优的性能与光影组合，远超 OptiFine。
    *   **特征**：Sodium（氪金）能提供 3~5 倍的帧率提升，Iris 则是与之完美兼容的光影 API。**此组合当前主要支持 Fabric 和 NeoForge 环境**。
    *   **操作**：和下载模组的操作是一样的，前提是确保游戏版本环境是Fabric或者是Neoforge。

## 3.3 离线安装方案 (本地文件安装)

若手机网络环境不佳，FCL 内置下载模块无法正常工作，可通过“从本地文件安装/升级”：

1.  在手机浏览器中，下载模组加载器官方的独立安装包（如 `forge-1.20.1-installer.jar`）。
2.  将 `.jar` 文件保存至手机本地存储中。
3.  在 FCL 的此界面点击底部蓝色按钮 **“从本地文件安装/升级”**。
4.  在系统文件选择器中选中该 `.jar` 文件，FCL 将自动解析并完成安装。

## 3.4 切换加载器的实操方案 (版本隔离)

若当前版本已安装 Forge，但因游玩需求希望切换至 Fabric，绝不可强行覆盖。推荐以下两种方案：

*   **方案 A：卸载重装模组加载器**
    *   **操作**：在 `自动安装` 界面中，找到目前已安装的 Forge ，点击左侧的 **`X`** 图标将其卸载，随后即可自由安装 Fabric。
    *   **注意**：`X` 代表**移除**，若当前版本曾安装过模组，点击 `X` 后其内置的模组及配置也需要一并清空。

*   **方案 B：版本隔离**（🚀 **专业开发者推荐方案**）
    *   **操作**：无需卸载当前版本。退回到 `下载游戏版` 界面，下载新的游戏版本，**确保FCL启动器开启了“版本隔离”**。
    *   **优势**：在此新版本内安装 Fabric，其操作**不会对原 Forge 版本产生任何干扰**。两个加载器的模组、存档、配置文件完全分离。

## 3.5 游戏版本阶段划分 (实践选型指南)

截至 2026 年，Minecraft Java 版已发布至 26.2。
游戏版本的选择直接决定了“可用的模组”与“加载器环境”。出于技术稳定性与模组丰富度的考量，实际社区中公认的“黄金版本”高度集中。针对此进行专业划分，将帮助新手精准选型：

*   ** 远古模组期（1.8.9 及以前）**
    *   **代表版本**：1.7.10、1.8.9。
    *   **运行环境**：Java 8。1.7.10 是模组史上的传奇版本，至今存有大量经典整合包。
    *   **FCL 选型建议**：这类古老版本与现行主流优化模组完全不兼容。**若非刻意怀旧，不建议新手触碰此类版本。**

*   ** 模组黄金巅峰期（1.12.2 ~ 1.16.5）**
    *   **代表版本**：1.12.2、1.16.5。
    *   **运行环境**：1.12.2 处于 Java 8 的末班车，1.16.5 则是对 Java 16 的初步适配。
    *   **模组生态**：**1.12.2 被誉为“万物皆可模组化”的终极巅峰**，绝大多数的硬核科技、魔法模组在此版本均有最成熟的稳定版。
    *   **FCL 选型建议**：若目的是游玩**“远古大包”**（如《更好的 Minecraft》），优先锁定 1.12.2 与 1.16.5，且模组加载器首选 **Forge**。

*   ** 底层架构大改期（1.17.x ~ 1.19.x）**
    *   **代表版本**：1.18.2、1.19.2。
    *   **运行环境**：强行切换至 Java 17 及以上。Forge 在这个时期遭受底层重构痛楚，启动极慢；取而代之的是 **Fabric 在此期间的强势崛起**。
    *   **FCL 选型建议**：若目标是玩**现代化的生存/小游戏模组包**，本阶段的 Fabric 环境搭配 Sodium 优化模组，性能表现极佳。

*   ** 现代主流期（1.20.x ~ 1.21.x+）**
    *   **代表版本**：**1.20.1**、1.21.1。
    *   **运行环境**：Java 17 与 Java 21。
    *   **模组生态**：**NeoForge 在本阶段彻底替代了传统 Forge 的地位**。稳定、轻量的 Fabric 依然活跃。
    *   **FCL 选型建议**：对于绝大多数 FCL 新手，**强烈推荐首选 `1.20.1` 版本**。该版本拥有全网最丰富的现代化模组资源、高度成熟的优化模组以及最为稳定的光影兼容体验。

---

** 新手定心结论**：
选版本时请牢牢记住这句口诀：**“老整合包看 1.12.2，新整合包首选 1.20.1。”**
请务必牢记，**你安装的 Mod 版本必须与你当前的游戏版本完全一致**（比如你装的是 `1.20.1` 的加载器，如果下载了一个 `1.19.2` 版本的 Mod 丢进去，游戏 100% 会崩溃。这是新手最容易犯的错！）
