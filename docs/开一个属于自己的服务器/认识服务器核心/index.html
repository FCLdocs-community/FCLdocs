专有名词

本文涉及到的专有名词：服务器、插件、Java

认识服务器核心

服务器核心是什么？​

服务器核心（Server Core）就是运行 Minecraft 服务器的程序。你下载一个 .jar 文件，用 Java 运行它，它就变成一个 Minecraft 服务器，其他人就能连进来一起玩。

根据需求不同，常见核心主要分这几类：

  • 原版核心（Vanilla）：Mojang 官方出品，最干净，但不支持插件和 Mod。
  • 插件核心（Plugin Core）：通过插件扩展功能，客户端无需装任何东西。适合生存服、小游戏服等需要管理、保护的场景，是新手最推荐的选择。代表：Spigot、Paper、Purpur。
  • 模组核心（Mod Core）：必须客户端和服务端同时装 Mod，能大幅改变游戏内容（新维度、新生物、科技魔法等）。代表：Forge、NeoForge、Fabric。
  • 混合核心（Hybrid Core）：兼顾模组和插件，稳定性通常弱于纯插件核心。代表：Arclight、Mohist。
  • 代理端（Proxy）：连接多个子服务器（大厅、生存服、小游戏服等），本身不含世界，只负责分发玩家。代表：Velocity。

为什么有这么多服务器核心？​

因为 Mojang 官方提供的 Vanilla 核心优化较少，而且不支持插件和 Mod。

打个比方：

  • Vanilla 就像一台裸机电脑，装了系统但什么软件都没有。能用，但功能少。
  • 第三方核心（Paper、Fabric 等）就像装了优化工具和应用商店的电脑。功能更全、性能更好。

社区开发者不满足于官方的简单版本，于是基于官方代码做了各种改进，形成了今天的"服务器核心生态"。

Vanilla（原版）​

Vanilla 是 Mojang 官方发布的服务器核心，和客户端版本一一对应。

特点：

  • 纯原版：没有任何修改，最"干净"。
  • 不支持插件：没有 Bukkit API，装不了插件。
  • 不支持 Mod：没有 Forge / Fabric，装不了模组。
  • 优化较少：没有额外的性能补丁，在玩家较多、红石复杂或区块加载量大时容易卡顿。2-3 人小服完全够用。
  • 适合人群：和朋友两三个人玩原版生存，不需要任何额外功能。
备注

Vanilla 是 Mojang 官方出品，每个游戏版本都有对应的 Vanilla 核心。你可以从 Minecraft 官网 下载。

插件核心​

插件核心（又称 Bukkit 系核心）通过 Bukkit API 支持插件，服主可以用插件管理领地、经济、权限等。玩家客户端无需安装任何 Mod。

Spigot​

Spigot 是历史最悠久、使用最广泛的第三方核心之一。它在 Vanilla 基础上做了大量性能优化，并支持 Bukkit 插件。

特点：

  • 性能优化：比 Vanilla 快很多，支持更多玩家同时在线。
  • 支持插件：兼容大部分 Bukkit / Spigot 插件。
  • 配置丰富：spigot.yml、bukkit.yml 等文件提供大量可调参数。
  • 生态成熟：市面上绝大多数插件都是为 Spigot 写的。
  • 适合人群：想开小型插件服务器的服主。

Paper​

Paper 是 Spigot 的下游分支，在 Spigot 的基础上做了更彻底的性能优化和更多 API。目前是最广泛使用的服务器核心。

特点：

  • 极致性能：红石优化、区块加载优化、实体管理优化……各方面都比 Spigot 更快。
  • 向下兼容：99% 的 Spigot 插件都能在 Paper 上直接跑。
  • 更多 API：提供了 Paper 独有的 API，让插件能做更多事（比如更细粒度的方块交互控制）。
  • 修 Bug：主动修复了大量原版 Minecraft 的 Bug（如刷物品漏洞）。
  • 活跃维护：更新快，新版本紧跟 Minecraft 版本。
  • 适合人群：绝大多数服务器的首选。无论是小服还是百人大服。
提示

如果你不确定选哪个核心，默认选 Paper。它是目前最平衡、生态最好的选择。

Leaves​

Leaves 是 Paper 的下游分支，由国人团队维护。它在 Paper 的基础上还原了部分被 Paper 移除的原版特性，并内置了假人（FakePlayer）支持及多种客户端 Mod 通讯协议。

特点：

  • 还原原版特性：Paper 为了性能或修 Bug，会禁用一些原版机制（如某些刷怪机制、红石行为）。Leaves 通过配置项把它们加回来，给服主更多选择。
  • 假人支持：服务端原生支持假人（FakePlayer），用于挂机、区块加载、农作物生长等。
  • 协议支持：内置 Syncmatica、Litematica、Jade、XaeroMap 等客户端 Mod 的通讯协议，无需额外安装插件。
  • 兼容 Paper 插件：Paper 的插件都能在上面跑。
  • 适合人群：想要 Paper 性能，但希望保留更多原版机制的服主；有假人或原理图分享需求的服主。

Leaf​

Leaf（Winds-Studio/Leaf）是另一个国人团队维护的 Paper 下游分支。和 Leaves 名字相似但不是同一个项目——Leaf 的定位是集大成的高性能分支，融合了来自 Gale、Pufferfish、Purpur、Leaves、Luminol 等众多分支的优化补丁。

特点：

  • 融合多分支优化：将多个 Paper 下游分支的优秀补丁整合到一个核心中，包括异步寻路、异步生物生成、异步实体追踪等。
  • Purpur 级自定义：继承了 Purpur 的游戏特性配置。
  • Mod 协议支持：同样内置客户端 Mod 通讯协议。
  • 线性区域文件格式：节省磁盘空间。
  • 兼容 Paper 插件：Paper 的插件都能在上面跑。
  • 适合人群：想要"一个核心吃遍所有优化"的服主，不想在不同分支间纠结取舍。

Paper 分支如何选择？

Paper → Pufferfish：追求极致性能（部分异步处理、实体优化、Sentry 集成），适合 50+ 人服务器。

Paper → Purpur：高度可定制，可改动物行为、游戏机制等，自由度极高。

Paper → Leaves（LeavesMC）：还原原版机制 + 假人支持 + 内置客户端 Mod 协议，侧重"原版体验补完"。

Paper → Leaf（Winds-Studio）：融合多分支（Gale/Pufferfish/Purpur/Leaves 等）的优化补丁，"集大成"性能向。

四者均为 Paper 的并行分支（Leaf 也融合了 Pufferfish/Purpur 的补丁），可按需选择。

Pufferfish​

Pufferfish 是 Paper 的下游分支，专注于极致性能优化。适合 50+ 人中型服务器在保持插件兼容性的同时追求更高 TPS。

特点：

  • 部分异步处理：将部分重负载工作卸载到其他线程，在不牺牲稳定性的前提下提升性能。
  • 实体性能优化：通过跳过无用的工作量来减少实体的性能开销。
  • Sentry 集成：内置错误追踪，方便服主排查问题。
  • 地图渲染加速：最高 8 倍速，减少 ImageOnMap 等插件导致的卡顿。
  • 漏斗/GC/寻路优化：漏斗提速 30%、减少 GC 频率、光追寻路加速等。
  • 兼容 Paper 插件：Paper 的插件都能在上面跑。
  • 适合人群：想要 Paper 生态但需要更高性能的服主，尤其是 50 人以上的生存服。

Purpur​

Purpur 是 Paper 的下游分支，在 Paper 的基础上增加了大量可自定义的游戏特性，并融合了多个分支的优化补丁。你能通过配置文件改动物行为、游戏机制等，自由度极高。

特点：

  • 高度可定制：可以改动物刷新、骑乘、方块掉落……几乎一切都能调。
  • 高度可定制：可以改动物刷新、骑乘、方块掉落……几乎一切都能调。
  • 兼容 Paper 插件：Paper 的插件都能在上面跑。
  • 适合人群：想要极致控制服务器各项机制的服主。
核心关系图
Vanilla → Spigot → Paper → Pufferfish（极致性能）
                         → Purpur（高度可定制）
                         → Leaves（原版还原、假人、协议）
                         → Leaf（集大成，融合多分支优化）
                         ↘ Folia（多线程实验分支）→ Luminol（Folia 生态分支）

Folia​

Folia 是 Paper 团队开发的实验性核心，最大的特点是多线程支持——能把多个区块交给不同 CPU 核心同时处理。

打个比方：Paper 是单车道，所有车（区块）排队通过一个收费站。Folia 是多车道，每辆车走不同的收费口，同时处理，速度快很多。

特点：

  • 多线程区块处理：不同区块在不同线程上独立运算，充分利用多核 CPU。
  • 性能飞跃：在大型服务器上，TPS 表现远超 Paper。
  • 插件兼容性差：大部分现有插件不兼容 Folia，因为多线程模型要求插件重写。
  • 不成熟：仍在开发中，可能会遇到 Bug。
  • 适合人群：不推荐新手使用。适合有开发经验、愿意尝鲜的大型服务器。

Folia 还有一些社区分支，如 Luminol（由 LuminolMC 团队维护），在 Folia 基础上增加了更多功能和优化。如果你关注 Folia 生态，Luminol 值得了解。

模组核心​

模组核心在服务端加载 Mod（模组），玩家客户端也必须装相同的 Mod 才能进入。Mod 可以添加新维度、新生物、科技系统、魔法系统等，大幅改变游戏内容。

Forge​

Forge 是最老牌的 Mod 服务端核心，拥有最庞大的模组生态。

特点：

  • 支持 Mod：可以装各种 Forge 模组（工业、魔法、科技……）。
  • 不支持插件：原生不支持 Bukkit 插件。
  • 版本覆盖广：从远古的 1.7.10 到最新的 Minecraft 版本都有 Forge。
  • 生态庞大：有数以万计的模组。
  • 性能一般：模组多了会很卡，需要加优化模组。
  • 适合人群：想开模组服务器的服主。
备注

从 1.20.1 版本起，越来越多的模组开发者转向 NeoForge（Forge 的社区驱动分支）。Forge 本身仍在活跃更新并支持最新 Minecraft 版本，两者并行发展。如果你开新版模组服，NeoForge 正逐渐成为首选。

NeoForge​

NeoForge 是从 Forge 分叉出来的新项目，由社区驱动、决策更透明。从 Minecraft 1.20.1 起，新建模组项目中 NeoForge 的使用比例持续增长。

特点：

  • 社区驱动：由社区维护，决策更透明。
  • 模组生态：逐渐成为新版模组（1.20.1+）的热门选择。
  • 适合人群：想在较新 Minecraft 版本上开大型模组服的服主。

Fabric​

Fabric 是新一代轻量级 Mod 加载器，和 Forge 是竞争关系。Fabric 更轻量、更新更快。

特点：

  • 支持 Mod：可以装 Fabric 模组。
  • 轻量：本身占用资源少，启动快。
  • 更新快：新 Minecraft 版本发布后，Fabric 往往几天内就支持。
  • 不支持插件：原生不支持 Bukkit 插件。
  • 生态：模组数量不如 Forge 多，但涵盖主流需求（优化、小地图等）。
  • 适合人群：想开轻量级模组服、或用 Fabric 优化模组（如 Sodium、Lithium）提升性能的服主。

Fabric 还有一个社区分支 Quilt，兼容 Fabric 模组，目前生态较小，新手直接用 Fabric 即可。

兼容层​

兼容层让一个平台的 Mod 能在另一个平台上运行，省去等待模组作者移植的时间。但兼容层本质是翻译，会有性能和稳定性损耗。

Sinytra Connector：让 Fabric Mod 在 NeoForge 上运行，有官方兼容性数据库标注哪些 Mod 可正常使用。

Kilt：让 (Neo)Forge Mod 在 Fabric 上运行。极不稳定，官方自称"可能损坏世界或导致崩溃"，不推荐生产环境使用。

注意

兼容层不是完美的。部分 Mod 在兼容层下可能崩溃、功能异常或性能下降。开服前务必测试。

混合核心​

有些服务器核心尝试同时支持插件（Bukkit API）和 Mod（Forge/Fabric API），满足"既要装插件，也要装 Mod"的需求。这类核心叫混合核心（Hybrid Core）。

Mohist 注意

Mohist 项目已被出售并转移至 Tenet（Teneted/Tenet），原 MohistMC 团队已不再维护。Tenet 目前维护 1.20.1 版本，但未来走向不明朗。如果你在 1.21.1 版本需要类似功能，MohistMC 原团队推出了 Youer（NeoForge 混合核心），或可选择 Arclight。

混合核心共同特点：

  • 一箭双雕：能装插件也能装 Mod。
  • 不完美：Bukkit 和 Forge/Fabric 两个体系底层架构差异大，对接通过代码映射（remap）实现，技术难度高、维护成本大，兼容性和稳定性难以保证。
  • 不推荐新手：出了问题很难排查。
  • 适合人群：有经验的服主，有明确的需求（如既要领地插件又要科技模组）。
注意

混合核心因底层架构差异大，往往不够稳定。遇到崩溃时，开发者通常会让你先排查自身问题。新手如果没有刚需，尽量别碰。

Sponge​

Sponge 是另一种 Mod+插件解决方案，但它走的是完全不同的路线——不用 Bukkit API，而是提供自己的 Sponge API。它不是一个混合核心，而是一个运行在 Forge/NeoForge/原版之上的独立插件平台。

特点：

  • 独立插件 API：不是 Bukkit 兼容，生态独立，插件需要通过 Ore 下载。
  • 三种形态：SpongeForge（跑在 Forge 上）、SpongeNeo（跑在 NeoForge 上）、SpongeVanilla（跑在原版上）。
  • 稳定性优于混合核心：因为是官方支持的集成方式，不像混合核心那样靠 remap 强行桥接。
  • 需为 Sponge 专门编写插件：运行的插件必须基于 Sponge API 开发或适配，不能直接使用 Bukkit 插件。
  • 适合人群：需要 Mod+插件的服主，且愿意接受 Sponge 的小众插件生态。

Cardboard（Fabric 版 Bukkit 兼容）​

Cardboard 是一个运行在 Fabric 服务器上的 Mod，让 Fabric 服务器能加载 Bukkit 插件。

  • 原名 Bukkit4Fabric。
  • 插件兼容性极差，即使是简单插件也大概率无法正常运行。不推荐任何生产环境使用。

代理端（Proxy）​

代理端不是一个完整的服务器核心，它是一个转发器——能把不同服务器连接到一个网络里，让玩家可以在多个服务器之间传送。

常见的代理端：

核心特点
BungeeCord最早的代理端，但更新已非常缓慢。
WaterfallPaper 团队维护的 BungeeCord 分支，已停止维护（EOL），不推荐新服使用。
Velocity新一代代理端，Paper 团队出品，性能最强、最稳定。⭐ 当前推荐

特点：

  • 连接多个子服：大厅、生存服、小游戏服、创意服可以分开。
  • 跨服传送：玩家通过传送门或命令在不同子服间切换。
  • 不运行游戏逻辑：代理端不加载世界、不处理生物 AI，只负责转发数据。
  • 适合人群：需要开多个子服的服主（如群组服、小游戏服）。

我该选哪个？​

如果你是第一次开服​

选 Paper。它性能好、插件多、社区大，遇到问题容易找到答案。

Vanilla     → 人少随便玩
Spigot      → 小服，需要基础插件
Paper       → 绝大多数场景 ⭐ 推荐
Pufferfish  → Paper 之上追求极致性能（50+ 人服）
Purpur      → 想极致调教服务器参数
Leaves      → Paper 基础上还想要原版特性/假人支持（LeavesMC）
Leaf        → 集大成高性能分支，融合多项目优化（Winds-Studio）

如果你想开模组服​

Forge    → 经典大型模组（新老版本均支持，仍在活跃更新）
NeoForge → 1.20.1+ 新版本模组服，社区驱动 ⭐ 上升趋势
Fabric   → 轻量优化模组，新版本更新快
Quilt    → 兼容 Fabric，生态小，新手直接用 Fabric 即可

如果你想"插件 + Mod"都要​

不建议新手尝试。如果确有需求：

  1. 首选 Sponge：更稳定但插件生态小。
  2. 次选混合核心：兼容性、稳定性均不如 Sponge。
  3. 避免兼容层：Sinytra Connector / Kilt 仍不成熟。

如果你想开多子服（群组服）​

主服务端用 Paper 开多个子服（生存服、小游戏服、大厅……），加一个 Velocity 做代理端。

Velocity（代理） → 大厅子服（Paper）
                → 生存子服（Paper）
                → 小游戏子服（Paper）

关键概念：TPS 和 MSPT​

在看不同核心的性能时，你经常会在文档中看到 TPS 和 MSPT 这两个词：

概念全称含义
TPSTicks Per Second每秒处理的游戏刻数，理想值是 20。
MSPTMilliseconds Per Tick处理一个游戏刻所用的毫秒数，越低越好。
提示

在服务器内输入命令 /tps 即可查看当前 TPS。Paper 及其下游核心（Leaves、Purpur 等）均支持此命令。

版本必须匹配​

版本必须匹配

服务器核心的版本号默认需要和玩家客户端的 Minecraft 版本一致。例如：Paper 1.21 只能让 Minecraft 1.21 客户端进入。

如果你的朋友版本不同，可以用 ViaVersion + ViaBackwards 等跨版本插件让低版本/高版本客户端也能进入。但跨版本插件会略微影响性能和兼容性，稳定性不如同版本直连。
